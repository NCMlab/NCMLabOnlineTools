# How To: Add a New UI Label (with EN/FR/KR translations)

> **Authorship notice**
> This document was generated by **Claude Code (model: claude-sonnet-5)** on **2026-07-08**.

A "label" here means one entry in `LabelNames` — the shared button/UI text (e.g. `Quit`,
`Home`, `Submit`) read by nearly every task's HTML page via `pseudoSwitch(LANG+'_LabelNames')`.
See `DiscussionLog.md` (Table 6) for why this lives in its own `ui_labels` table instead of
`task_parameters`.

**Important — there are two copies today, and only one of them is live.** Every HTML page in
`html/JATOS/` still reads `LabelNames` from `config/General_Setup.js` at runtime — nothing
reads from the `ui_labels` database table yet (no API endpoint fetches it). So:

- `config/General_Setup.js` is the copy that actually affects the running study today. Always
  edit this.
- The `ui_labels` table is a forward-looking mirror, kept in sync by regenerating from the JS
  source. Update it too, so it doesn't drift out of date before the database becomes the real
  source of truth.

---

## Step 1 — Pick a label key

Use `PascalCase`, no spaces — it becomes a JavaScript object property name (`LabelNames.YourKey`)
and a SQL `label_key` value. Check it isn't already used:

```bash
grep -n "EN_LabelNames\.YourKey" config/General_Setup.js
```

---

## Step 2 — Add it to `config/General_Setup.js` (the live source)

There are three blocks in this file — `EN_LabelNames`, `FR_LabelNames`, `KR_LabelNames` — each
built with one dot-assignment line per key, e.g.:

```js
EN_LabelNames.Quit = 'Quit'
```

Add one new line to **each of the three blocks** (not just one — a label missing from a
language silently falls back to nothing being shown for that key on that language's pages).
Example — adding a `ConfirmExit` label:

```js
// inside the EN_LabelNames block (around line 17-64)
EN_LabelNames.ConfirmExit = 'Are you sure you want to exit?'

// inside the FR_LabelNames block (around line 66-113)
FR_LabelNames.ConfirmExit = 'Êtes-vous sûr de vouloir quitter?'

// inside the KR_LabelNames block (around line 116-162)
KR_LabelNames.ConfirmExit = '정말로 종료하시겠습니까?'
```

You do **not** need to touch the three `add(...)` lines at the bottom of the file (lines
164-166) — they register the whole object, not individual keys, so a new key on an existing
object is picked up automatically.

Save the file. This is now live for every task's HTML page.

---

## Step 3 — Add it to the `ui_labels` table

### Recommended: regenerate from source (keeps everything in sync)

```bash
cd MySQL/ConfigurationDatabase/migrate
node extract.js
node generate_sql.js
```

This re-reads `config/General_Setup.js` and rewrites `Migrated_TaskConfig.sql` with **every**
label row, not just the new one. That's safe to re-apply to a live database because every
insert is `INSERT IGNORE` and `ui_labels` has `UNIQUE(label_key, language)` — rows that already
exist are silently skipped, and only the 3 new `ConfirmExit` rows (EN/FR/KR) actually insert:

```bash
mysql -u ncmuser -p ncmbattery_config < Migrated_TaskConfig.sql
```

**Caveat:** because existing rows are skipped, this workflow only *adds* new keys cleanly. If
you're changing the *wording* of a label that already exists, `INSERT IGNORE` will NOT update
it — see the note at the bottom of this file.

### Alternative: manual SQL (quick one-off, but drifts from the JS source)

```sql
USE ncmbattery_config;
INSERT INTO ui_labels (label_key, language, label_value) VALUES
('ConfirmExit', 'EN', '"Are you sure you want to exit?"'),
('ConfirmExit', 'FR', '"Êtes-vous sûr de vouloir quitter?"'),
('ConfirmExit', 'KR', '"정말로 종료하시겠습니까?"');
```

Note `label_value` is a JSON column — plain text values must be wrapped in `"..."` (double
quotes) as shown. A few existing labels are arrays instead of strings, e.g.:

```sql
INSERT INTO ui_labels (label_key, language, label_value) VALUES
('SomeChoicePair', 'EN', '["Option A","Option B"]');
```

If you use this path, also make the same edit in `config/General_Setup.js` (Step 2) by hand so
the two copies don't disagree.

## Step 4 — Verify

Check the key exists in all three languages:

```sql
SELECT language, label_value FROM ui_labels WHERE label_key = 'ConfirmExit';
```

Expect 3 rows (EN, FR, KR). If you get fewer than 3, one language's dot-assignment line in
`config/General_Setup.js` was likely missed before regenerating — go back to Step 2.

Check for any label missing a translation project-wide (useful after any edit, not just this
one — see `ToDo.md` for the known pre-existing `Info` gap in FR/KR):

```sql
SELECT label_key FROM ui_labels WHERE language='EN'
  AND label_key NOT IN (SELECT label_key FROM ui_labels WHERE language='FR');

SELECT label_key FROM ui_labels WHERE language='EN'
  AND label_key NOT IN (SELECT label_key FROM ui_labels WHERE language='KR');
```

## Editing the wording of an existing label

Regenerating from source will **not** overwrite an existing `(label_key, language)` row — the
migration script uses `INSERT IGNORE` specifically so re-running it is safe and never clobbers
manual database edits. To change existing text, update both copies directly:

```js
// config/General_Setup.js
EN_LabelNames.Quit = 'New wording here'
```

```sql
UPDATE ui_labels SET label_value = '"New wording here"'
  WHERE label_key = 'Quit' AND language = 'EN';
```
