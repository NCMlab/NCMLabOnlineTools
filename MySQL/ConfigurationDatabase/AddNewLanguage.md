# How To: Add a New Language to `ui_labels`

> **Authorship notice**
> This document was generated by **Claude Code (model: claude-sonnet-5)** on **2026-07-08**.

**Scope note:** this document covers adding a new language's UI button labels (`ui_labels`
only) — the shared text like `Quit`, `Home`, `Submit`. It does **not** cover translating a
task's actual instructions/parameters (`task_instructions`, per task, e.g.
`InstructionsAndStimuli/Instructions/WordRecall_Instructions.js`), word lists, or adding the new
language as a selectable option in `LanguageSelection.html` / a battery's `LanguagesToShow`
array in `Batteries/Batteries.js` — those are separate, larger efforts (see `ToDo.md`).

Same caveat as `AddNewLabel.md`: `config/General_Setup.js` is the copy every HTML page actually
reads at runtime today; `ui_labels` is a forward-looking mirror with no live consumer yet. Both
need updating.

Example throughout: adding Spanish, language code `ES`.

---

## Step 1 — Pick a 2-letter language code

The `language` column is `CHAR(2)` everywhere in this schema (`ui_labels`, `task_parameters`,
`task_instructions`, `batteries`), so it must be exactly 2 characters. The existing codes are
`EN`, `FR`, `KR` — note `KR` is this codebase's own convention, not strict ISO 639-1 (which
would be `KO`), so match the project's existing style rather than looking up a standard.

---

## Step 2 — Add the label object to `config/General_Setup.js`

Copy the `EN_LabelNames` block (lines 17-64) as your template — it has the full/canonical set of
47 keys — and translate every value. Do **not** copy `FR_LabelNames` or `KR_LabelNames` as the
template; both are already missing a key or two versus `EN` (see `ToDo.md`), and copying them
would carry that gap into the new language too.

```js
var ES_LabelNames = {}
ES_LabelNames.NoYes = ['No','Sí']
ES_LabelNames.YesNo = ['Sí','No']
ES_LabelNames.Home = 'Inicio'
ES_LabelNames.Restart = 'Reiniciar'
ES_LabelNames.Info = 'Información'
ES_LabelNames.Stop = 'Detener'
ES_LabelNames.Quit = 'Salir'
ES_LabelNames.Skip = 'Omitir'
ES_LabelNames.Finished = 'Terminado'
// ... continue for every key in EN_LabelNames -- see full list below
```

Full key list to translate (from `EN_LabelNames`, 47 keys as of 2026-07-08): `NoYes`, `YesNo`,
`Home`, `Restart`, `Info`, `Stop`, `Quit`, `Skip`, `Finished`, `ProcessSpeech`, `Clear`, `Undo`,
`Redo`, `Repeat`, `Next`, `Continue`, `Previous`, `Enter`, `Submit`, `SubmitAnyway`,
`SubmitAnywayAreYouSure`, `Done`, `Other`, `CurrentAnswer`, `Correct`, `Incorrect`, `Same`,
`Different`, `PressNext`, `WordListA`, `WordListB`, `ProgressBar`, `PleaseRead`,
`SelectMicrophone`, `UseThisMicrophone`, `NoteInputBox`, `NonEligible`, `BroswerNonEligible`
(sic — typo already in the source, keep it as-is for consistency), `StopStudy`, `ExitStudy`,
`SkipTask`, `missed_question_label`, `missed_question_text`, `ThankYou`, `Hello`, `EnterName`,
`TrailMakingRemaining`.

Add the new block right after the existing three (after line 162, before the blank line at 163).

---

## Step 3 — Register it

Add one line next to the existing three `add(...)` calls (currently lines 164-166):

```js
add('EN_LabelNames', function(){ LabelNames = EN_LabelNames});
add('FR_LabelNames', function(){ LabelNames = FR_LabelNames});
add('KR_LabelNames', function(){ LabelNames = KR_LabelNames});
add('ES_LabelNames', function(){ LabelNames = ES_LabelNames});
```

This is what makes `pseudoSwitch('ES_LabelNames')` work — every HTML page calls
`pseudoSwitch(LANG+'_LabelNames')`, so once a page's `LANG` variable is `'ES'`, this line fires.
(Making `LANG` actually reach `'ES'` requires the `LanguageSelection.html` / `LanguagesToShow`
work mentioned in the scope note above — out of scope here.)

---

## Step 4 — Teach the migration script about the new code

`migrate/extract.js` detects a registration's language from a fixed prefix list:

```js
const KNOWN_LANG_PREFIXES = ['EN', 'FR', 'KR'];
```

Add `'ES'`:

```js
const KNOWN_LANG_PREFIXES = ['EN', 'FR', 'KR', 'ES'];
```

Without this, the extractor still captures the `ES_LabelNames` registration, but tags it with
`language: null` instead of `'ES'`, and `generate_sql.js` would fall back to inserting it as
`'EN'` (its default) — silently wrong. Don't skip this step.

---

## Step 5 — Regenerate and apply

```bash
cd MySQL/ConfigurationDatabase/migrate
node extract.js
node generate_sql.js
mysql -u ncmuser -p ncmbattery_config < Migrated_TaskConfig.sql
```

Because every insert is `INSERT IGNORE` against `UNIQUE(label_key, language)`, this only adds
the ~47 new `ES` rows — the existing EN/FR/KR rows are untouched.

---

## Step 6 — Verify

Row count matches the other languages:

```sql
SELECT language, COUNT(*) FROM ui_labels GROUP BY language;
```

Check for any key you missed translating (compares against `EN`, which has the full canonical
set):

```sql
SELECT label_key FROM ui_labels WHERE language='EN'
  AND label_key NOT IN (SELECT label_key FROM ui_labels WHERE language='ES');
```

An empty result means full coverage.
