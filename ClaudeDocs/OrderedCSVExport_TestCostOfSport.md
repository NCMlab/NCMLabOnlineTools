## What changed

1. Removed the broken, unused file-input stub (`readFileAsText` / `processFiles`). It referenced a `headerFile` `<input>` element that does not exist anywhere in the page, and it logged an undefined `result` variable — it could not have worked as written.

2. Added four functions in its place:
   - `parseCSVText(text)` — a small CSV parser that handles quoted fields, embedded commas, and CRLF/LF line endings. Also strips a leading UTF-8 BOM (`CodeBookSheet.csv` is saved with one).
   - `loadCodeBookHeaders(url)` — `fetch`s `CodeBookSheet.csv`, parses it, and returns the ordered list of column names from its first column. Trims whitespace and normalizes stray non-breaking spaces (found in row 2 of the current file, `"SP_Level "`) to regular spaces.
   - `objectToOrderedCSV(dataObj, headers)` — builds a CSV string (header row + one data row) with columns in exactly the order given by `headers`. Any header not present as a key on `dataObj` is written as an empty field rather than being skipped or throwing.
   - `saveObjectAsOrderedCSV(dataObj, codeBookUrl, filename)` — combines the two functions above and calls the pre-existing `downloadCSV()` to trigger the browser download.

3. Wired the new functions into the `on_finish` callback of `initJsPsych(...)`. That callback is now `async` (needed to `await` the fetch of the codebook). It replaces the old `jsPsych.data.get().csv()` line — which produced columns in whatever order jsPsych happened to encounter them, the exact problem flagged in the code comment and Google search link that used to sit right above it — with:


   `temp2` is the already-flattened/unpacked response object built earlier in the same callback (dynamic-matrix arrays and objects unpacked into flat keys like `Sport_Curr1`, `Sport_Curr1_Context`, etc.).

## How to use it

- The column order is driven entirely by `assets/OutputDataFormatting/CodeBookSheet.csv` — one column name per line, in the order they should appear in the output file. To change the output column order or add/remove a column, edit that CSV file; no JavaScript changes are needed.
- When a participant finishes the survey in `Playground/TestCostOfSport.html`, a CSV named `CostOfSport_<timestamp>.csv` is downloaded automatically with columns in that order. Any codebook column whose name has no matching key in the response data is written as an empty cell instead of being omitted, so the output always has the full, fixed set of columns.
- To reuse this elsewhere (e.g. the production `html/JATOS/CostOfSport.html` page), copy the four functions and call `saveObjectAsOrderedCSV(dataObject, pathToCodeBookCsv, filename)`. Note the codebook path differs by page: `Playground/TestCostOfSport.html` uses a filesystem-relative path (`../assets/OutputDataFormatting/CodeBookSheet.csv`), while pages served through JATOS routing (like `html/JATOS/CostOfSport.html`) resolve relative paths against the study assets root, so the path there would be `assets/OutputDataFormatting/CodeBookSheet.csv` (no `../`).
- **Known gap, not addressed by this change:** the response object's keys (e.g. `annual_membership_fees`) do not all match the codebook's column names (e.g. `Cost_Memb`) yet. Columns whose names don't line up will export blank until the SurveyJS question `name` fields are aligned with `CodeBookSheet.csv`.
